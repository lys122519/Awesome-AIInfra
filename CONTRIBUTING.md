# Contributing

Thanks for helping maintain Awesome-AIInfra. This file is the single reference for review rules and the curation workflow.

## Data files

- `data/papers.yaml` is the canonical accepted-paper dataset.
- `data/rejected.yaml` records rejected candidates and their reasons, so they are not reviewed again.
- `README.template.md` holds the hand-written introduction. The paper block in `README.md` is generated by `scripts/generate_readme.py`; never edit it directly.

## Paper acceptance criteria

1. A paper must make a direct systems contribution to AI infrastructure, such as training, inference, serving, scheduling, communication, orchestration, accelerators, memory, storage, reliability, or benchmarking.
2. Papers that only apply an existing model to an application domain are out of scope.
3. For `publication`, prefer a DOI, publisher, OpenReview, or official conference URL.
4. Add `code` only when it points to the authors' or official project's repository.
5. Use one of the categories defined in `scripts/generate_readme.py`.
6. Search both `data/papers.yaml` and `data/rejected.yaml` for duplicates.
7. Set `reviewed: true`, `reviewed_at`, and `review_method` only after checking relevance, metadata, and category placement. Unreviewed candidates cannot pass validation.

Rejected candidates go into `data/rejected.yaml` with a short reason.

## Submitting changes

Human changes go through a pull request. Commit `data/papers.yaml` (and `data/rejected.yaml` if changed) together with the regenerated `README.md`, and run:

```bash
pip install -r requirements.txt
python scripts/generate_readme.py
python scripts/generate_readme.py --check
python -m unittest discover -s tests -v
```

## Screening tracker batches

`scripts/screen_candidates.py` produces precision-oriented accept/reject recommendations for a batch exported by the tracker. The recommendations are not accepted records by themselves: inspect the decision file, then apply it with:

```bash
python scripts/apply_screening.py path/to/screening-decisions.yaml --reviewed-at YYYY-MM-DD
python scripts/generate_readme.py
```

The importer is idempotent: decisions that were already applied are skipped, while a decision that conflicts with the accepted or rejected dataset stops the import.

## Automatic curation

`.github/workflows/auto-curate.yml` runs on days 7 and 21 at 01:15 UTC, one day after each scheduled tracker update. It exports and screens the tracker's active candidates, then applies only high-confidence accepts with `apply_screening.py --accept-only`. Automatic rejects are never recorded, so those candidates stay available for human review. The workflow regenerates the README, runs validation and tests, and commits the result directly to `main`. It must never import an entire tracker cache.
